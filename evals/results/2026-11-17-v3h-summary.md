## What the returns show

- **The tool checks made three cases deterministic.** LL-03, LL-04 and BK-05G each fail `check_ui.py` in the
  idiom gate, and every Verifier reported it as a major finding citing the run.
- **The clean case passes.** LL-05 passed in every run, so the new checks raised no false positive.
- **BK-05F failed in every run, the same way.**
  - Each Verifier returned `pass`, listed BK-05C's `Http404` under `inherited` as ruled, and added a not-found
    test.
  - None wrote the use-case test the prompt now asks for ("call the use case directly with input the rule must
    refuse"). In v3g one run did, and proved the defect.
  - This is the one remaining defect only a review can find, and the Verifier doesn't do that review reliably
    when nothing forces it.

## Decision

ADR-0043's done condition isn't met yet: BK-05F fails by majority, with no ruling. ADR-0043 stays **Proposed**.

Two ways forward, both harness decisions:
1. **Make the rule-placement review mechanical.** The finish check would require the Verifier's return to list
   each business rule in the ticket's scope, with the use-case test that shows where it's enforced. A missing
   entry blocks the return, as a missing mutation score does.
2. **Accept ADR-0043 at 6 of 7.** Record BK-05F as the known limit: a rule in the wrong layer is found by review
   in about one run of three.
