These runs measure harness #188 and eval #903. Step 3 of the Verifier prompt gained two checks: prove where
each rule is enforced (a test that calls the use case directly), and check that every error path renders,
including htmx 2's default of swapping no 4xx or 5xx response. There were three runs of the six Verifier
cases, compared with v3f by majority (`afs-eval compare`).

**4 of 6 by majority, the same count as v3f, but a different four.** `compare` reports that the change doesn't
hold, because BK-05G flipped from pass to fail. Sessions ran longer: median minutes rose 52% and requests 20%.

## What the two checks found

- **The checks find what they were written for.**
  - LL-03 r1 and r3 found the htmx 4xx/5xx defect, each with a test asserting the missing swap configuration.
  - BK-05F r1 proved the eligibility rule lives in the view: `CargoRouting.assign_route` accepts an
    out-of-spec itinerary when called directly.
- **They also produced serious findings on two clean cases.** Each finding is backed by a failing test, which
  the evidence rule demands, so none is an unproven claim. Each needs the operator's ruling:
  - **BK-05G r2: "htmx 404 responses are not configured to swap"** in the not-routed table's dialogs. An
    unknown or stale tracking ID leaves the dialog on its loading message. This is the same defect class the
    operator ruled real for LL-03, so it is likely BK-05G's own defect, and BK-05G would be a defect case.
  - **BK-05G r2: "edit actions have no native link or form fallback without JavaScript."** Progressive
    enhancement: whether this is a defect depends on whether the plan requires it to work without JavaScript.
  - **LL-04 r3: "the linked Tailwind asset lacks `.py-8`, `.mt-8` and `.leading-relaxed`".** LL-04's
    `about.html` uses classes the committed, pre-built `tailwind.css` doesn't contain, so the approved layout
    is incomplete. If real, it is LL-04's own defect, not inherited: the ticket wrote the template and didn't
    rebuild the CSS.
- **BK-05G r1 committed no return.** The session ran 52 minutes and stopped before writing it; the extra
  checks make sessions longer.
- **BK-05F r3** proved a different defect instead: both route screens return a generic 404, not #232's
  tracking-ID-specific not-found message. r2 returned `pass`, with the `Http404` correctly listed under
  `inherited`.

## Decision

Not done, and ADR-0043 stays **Proposed**. The next step depends on the operator's rulings on the three
findings above:
- **If the htmx 404 swap is real for BK-05G:** BK-05G becomes a defect case. Its r2 would pass on that finding
  and r3 would fail, so it stays 1 of 3 until the re-run.
- **If LL-04's missing Tailwind utilities are real:** LL-04 becomes a defect case, at 1 of 3.

Either way, the remaining misses are about consistency (the same check finds the defect in one run and not
the next), not a blind spot. The next lever is time: BK-05G r1 lost its return to session length.
