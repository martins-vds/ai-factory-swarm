# Phase 2b: the Bootstrapper folded into the Program Orchestrator (2026-11-19)

The bootstrap case (`synthetic-sy-01-bootstrap`) ran the Program Orchestrator with the new `afs-bootstrap`
skill, twice. Then, after one fix, it ran twice more.

| Run | Harness | Result | What happened |
|---|---|---|---|
| 2b-r1 | a68650a | fail | Ran `afs-setup-check` first, found no `.migration/harness/` (bootstrap's step 5 installs it) and handed off before steps 1–4 |
| 2b-r2 | a68650a | fail | Same |
| 2b-r3 | fold-bootstrapper + setup-check fix | **pass** | Tier A, `source.path` and `source.sha` written as the live run did |
| 2b-r4 | same | **pass** | Same |

**The fix:** at intake the harness isn't installed yet, so only `afs-setup-check`'s history check applies. The
setup check, the orchestrator's first line and `afs-bootstrap` now say so.

**Against the baseline:** b3c's Bootstrapper passed 3 of 3, and the folded orchestrator now passes 2 of 2.
No flip, so ADR-0046 can be accepted. Session cost isn't recorded: with no harness installed, the cost hook
isn't either.
