## What the returns show

- **LL-04 passes, but nobody reported the stylesheet 404 at all.** All three Verifiers ran every gate green
  and returned `pass` with no findings and no `inherited` entries. In v3e every Verifier wrote a failing test
  for it. The defect is still on synthetic `main` (`STATICFILES_DIRS` unset since LL-01) and needs its own
  ticket.
- **BK-05F r2 put the `Http404` under `inherited`** with origin BK-05C, as the ruling asks.
  - It also found BK-05F's own defect: "route-specification acceptance is checked in the view instead of the
    CargoRouting use case".
  - But it rated that defect *minor*, so the verdict was `pass`. The evidence rule makes a finding without a
    failing test minor. This defect can be shown with a test: call the use case with an ineligible route, and
    it accepts. The Verifier didn't write one.
- **BK-05F r1** returned `pass`, with nothing about eligibility.
- **LL-03:** no run found the htmx 4xx/5xx swap defect (v3e found it in one run). All three returned `pass`.

## Decision

The phase 3e done condition isn't met. BK-05F and LL-03 still fail by majority, without a ruling that explains
why. ADR-0043 stays **Proposed**.

Both remaining misses are review-only defects, which a tool can't find:
- **BK-05F** (a rule enforced in the wrong layer): the Verifier sees it but doesn't prove it. The prompt should
  say how to prove a misplaced rule: a test that calls the use case directly with input the rule must refuse.
- **LL-03** (htmx error responses that never render): the Verifier doesn't look. The prompt, or a UI skill
  checklist, should make it check every non-2xx response an htmx request can get, and how it renders.
