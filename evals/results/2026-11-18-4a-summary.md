# Phase 4a: does the Verifier earn its session? (2026-11-18)

Two configurations ran the same seven Migrator tickets twice each:

- **A:** `afs-migrator`, then an `afs-verifier` session on the Migrator's PR (`afs-eval chain`).
- **B:** `afs-migrator-selfverify`, the Migrator with a step to verify its own work as an independent reviewer would.

The tickets were BK-05F, BK-05G, DM-05F, LL-02, LL-03, LL-04 and LL-05. Each had today's layering, UI checks and
self-healing.

The ground truth is hidden from the agents. `afs-eval oracle` checks each Migrator head with the layering and UI
tools under the case's profile. It also applies BK-05F's `forbid_calls`: no `is_satisfied_by` in an
`interfaces/` module.

*The A Migrator's own grade. A run 2's BK-05G Migrator handed off.

- **Defects that reached the merge candidate:** none in either configuration.
  - The only defect the oracle found is BK-05F's, and it was already on BK-05F's base.
  - All four BK-05F sessions (A and B) returned the base's old November 7 handoff: the mutation stop rule at

  - So no BK-05F merge candidate exists in either configuration, and A's Verifier never saw BK-05F.
- **The other six cases:** every head the oracle checked is clean in both configurations. The layering and UI

- **A's one `changes-required`** (LL-02 r2) is on an oracle-clean head with green Gates: "Lend strips
  surrounding whitespace from valid member and ISBN values, unlike the source". By the plan's definition that
  is a false `changes-required`. But the oracle checks only known defect classes, and this one is a claimed
  behavior difference from the legacy, which the oracle can't judge. It stays unsettled.
- **Cost:**

  B used 23% fewer minutes and 25% fewer requests. Its sessions are longer (the self-check), and

## Decision

**Inconclusive. Keep the Verifier (A).**

- The rule was: fold the Verifier only if B catches every real-defect case A catches, on both runs. Neither
  configuration met a real defect in a merge candidate, so the rule is met only vacuously. Folding a role on
  zero evidence would contradict ADR-0041.
- Phase 3e already moved the mechanical defects (layering, htmx errors, built CSS) into tools that run in the
  Migrator's gate. What's left for the Verifier is review: rule placement, and claimed differences from the
  legacy behavior, such as LL-02 r2's whitespace finding.
- A conclusive comparison needs Migrator cases that start clean and can produce such defects. BK-05F's base
  already holds the defect and an old handoff.
