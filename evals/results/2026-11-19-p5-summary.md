Phase 5 trimmed the harness: skills by usage (ADR-0052) and role prompts under 6,000 characters
(ADR-0053). This eval runs every must-pass case on the phase 5 harness and compares it with the phase-1
baseline (`2026-11-15-baseline-r1`, `-r2`). The bar: no case that passed by majority in the baseline may
fail by majority now.

## Most sessions never tested the harness
Across the run files, 81 rows are `setup-failure`. Almost all of them failed "Install RTK 1.1.0" with
`release not found`, which skips every later setup step. Those agents started without Python, the
harness tools or a working RTK hook, and correctly stopped. ADR-0054 changed three things:
- RTK installs from the release URL.
- `grade` marks these rows `setup-failure`.
- `compare` doesn't count them as runs.

After eval #1864 put the fix on the eval repo's `main`, every session of `p5z-r1` installed RTK.

Two more corrections went into the counts:
- **Excluded runs:** the `.adj.json` files mark as `not-dispatched` the LL runs that started on a
  validation error. Each has an `excluded` note.
- **LL-01's error:** it was an eval-side defect, a re-planned plan committed together with the harness.
  Prepare now commits normalized files first and refuses a case that starts with errors (ADR-0054).

## The cases that needed more runs
- **pilot-bk-05f (1/3)**
  - `p5-r1` passed.
  - `p5x-r1` (PR 1769) handed off over a mutation-base mismatch.
  - In `p5z-r1` (PR 1909) the agent passed every gate (mutation 0.891, CodeQL 0 alerts). It then handed
    off a genuine scope question: the route-assignment eligibility rule is checked in the view but not
    enforced in `CargoRouting.assign_route`. Fixing that needs `application/routing.py` and its test,
    which the ticket's plan doesn't list. Its last commit was at 00:10. Copilot's own post-processing
    then idled until the job's timeout at 00:45, so the row reads `session-timed-out`.
  - The finding is a real defect in the live BK-05F plan. It's worth a ticket on the pilot.
- **pilot-bk-05f-fresh (3/7 over all harness versions; 2/2 on the final one).**
  - `p5x-r1` passed; `p5-r1` (PR 1603) failed.
  - **`p5z-r1`: mutation saw only commits.** The agent ran mutation before committing its new view. The
    tool reported `no-mutable-code-changed` and the agent recorded `n/a`; CI scored the view at 0.373.
    ADR-0055 makes `afs-mutation` count uncommitted and untracked files.
  - **`p5w-r1` and `p5w-r2` (after ADR-0055): the finish check let failing work stop.** The in-session
    mutation scores now matched CI's (0.667 against 0.674, 0.839 against 0.839).
    - r1 returned mutation 0.667 against 0.8 with no handoff.
    - r2 passed `idiom`, then edited code while raising mutation and never re-ran it. CI's ruff failed.
    - ADR-0056 refuses a return with a failing gate and no handoff, and a gate run before the latest code
      edit.
  - **`p5u-r1` and `p5u-r2` (after ADR-0056): both pass.** The finish check sent both back at least once:
    - for gates run before later test or code edits;
    - for `crap: 26.0`, the worst method's score where the schema wants the gate's exit code. The message
      now says so.
- **synthetic-billing-understand (1/3, not must-pass).**
  - The case needs the BL-02 Characterizer to run after the Analyst. The first two runs graded the
    Analyst alone, which my protocol missed.
  - The chained run (`p5zc-r1`, PR 1928) passes.
- **synthetic-sy-01-bootstrap (2/2 after ADR-0055).**
  - **`p5z-r1`: setup broke before bootstrap.** The services step called a harness tool the repository
    doesn't have until bootstrap, and the remaining setup steps were skipped. The agent also committed

  - **`p5v-r1` and `p5v-r2`: both pass, and setup passes.** Neither committed `.source`.
  - **Both committed 50 files of `legacy/target/`**, the Maven output of building the in-repo legacy
