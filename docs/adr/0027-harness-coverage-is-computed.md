# ADR-0027: Harness coverage is computed, and every tool announces that it ran

- Status: Accepted
- Date: 2026-11-03
- Issues: #43 (tool), #42 (the pilot's coverage map)

## Context
The pilot exists to verify the harness. Which harness paths it has exercised was first answered by
reading run journals, return files and their history, the ledger, issues and workflow runs by hand
(#42). A hand-made map goes stale, misses things, and has no definition of "exercised".

Workflow steps alone can't answer it either. A step that calls several tools passing says nothing
about any one of them. Neither does a step that calls a tool on only one branch: the graph workflow's
"prepare" step calls `extract_slice.py` only for per-slice graphs, which the pilot never built.

## Decision
1. **Every installed tool announces itself.** Each entry point is `afs_trace.run(main)`, which prints
   `AFS-TOOL <tool> exit=<code>` to stderr when the tool ends. `tests/test_trace.py` fails if a tool in
   `bootstrap.HARNESS_TOOLS` skips it.
2. **`harness_coverage.py` computes coverage.**
   - The universe is derived from the installed harness:
     - the return schema's roles, and each role's enums;
     - the ledger schema's enums;
     - the files in `.migration/harness/tools/`;
     - the generated workflows;
     - the `afs:`/`wayfinder:` labels.
   - The evidence is the repo's history:
     - every version of every return file and ledger entry;
     - run-journal rows that run a harness tool, with their exit codes;
     - `AFS-TOOL` lines in CI job logs;
     - workflow conclusions and labelled issues.
3. **"Exercised" means both paths.** A tool or workflow is ✅ only when it has been seen passing **and**
   failing; ⚠️ is one path only; ❌ is never. Step-level evidence, from runs before `AFS-TOOL` existed,
   is at most ⚠️.

4. **Agent sessions are evidence too** (amended after the first live report). Agents run tools inside
   their sessions, for example `check_inputs.py` from `afs-setup-check`, whose logs aren't kept. The
   session hook already reads the session log and commits a record (ADR-0021). It now lists the
   session's `AFS-TOOL` lines, itself included, under `harness_tools`, and coverage reads every version of
   those records.
5. **A tool is a file whose entry point is `afs_trace.run`.** Libraries (`afs_trace.py` itself) are not
   tools, so no list of exclusions is needed.

## Consequences
- The pilot's coverage map (#42) is regenerated by `harness_coverage.py --repo …`, not edited by hand.
- A new role, status, tool or workflow shows as ❌ the moment it ships, with no list to update.
- Evidence from before this ADR is mostly step-level, so the first report under-counts. Every run from
  now on adds exact evidence.

## Amendment (2026-11-06): drills, and tools without a verdict
- **Failure drills.** A check seen only passing gets its failing run on purpose: `tools/afs-drill` breaks one
  thing on a throwaway branch (a draft PR, a stacked PR, or a dispatched workflow) and confirms that the named
  check fails, from its `AFS-TOOL` line or the run's conclusion. The drills are data (`tools/drills.json`):
  operations whose paths come from the target's own profile and install record, so they run on any target.
  The PR is closed and the branch deleted, caught or not; the runs stay as evidence.
- **No verdict, no failing path.** A tool that reports and never blocks (cost records, the coverage report
  itself, opening the fog re-walk task) has no failing verdict to show. It declares that with
  `afs_trace.run(main, verdict=False)`, and a workflow with `# afs-coverage: no-verdict`. Coverage then
  needs to see it run, not fail. Errors in such tools still exit non-zero; they just aren't a path to drill.


### Amendment (2026-11-08): coverage keeps its evidence

On the pilot, `check_plan.py`, `check_runtime.py` and `afs-map-fog.yml` went from covered to open with no
change to the harness. Their failing drill runs had dropped out of the recent-runs window the report reads.
`--runs` was also silently capped at GitHub's 100-per-page limit. Coverage that expires isn't evidence.

`harness_coverage.py --keep` now records the first evidence seen for each side of each tool and workflow
in `.migration/evidence/coverage.json`: a run link, a journal gate, or an agent session. Every run reads
that file back, so a path once exercised stays exercised, with a link to its proof. The file is committed
like any other evidence. `--runs` now pages past 100.
